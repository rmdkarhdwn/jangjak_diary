# 장작일기

관심사를 작은 불로 표현하고, 오늘의 활동과 마음을 장작처럼 쌓는 Flutter 앱입니다.

[Figma 홈 화면](https://www.figma.com/design/E4G6JJEdjnJrWhTQ4AaY6E/?node-id=3043-193)을 기준으로 구현했습니다.

## 현재 동작

- 책 읽기, 기타 치기, 달리기 사이를 좌우로 넘길 수 있습니다.
- 상단 + 버튼 또는 캐러셀 끝의 빈 벽난로에서 새 관심사를 만듭니다.
- 홈의 모닥불이나 전체 분류 카드를 길게 누르면 ‘보관하기(추천) / 완전히 삭제하기 / 취소’를 선택합니다.
- ‘장작 넣기’에서 현재 관심사의 기록을 작성합니다.
- ‘기록 보기’에서 해당 관심사의 기록을 최신순으로 읽고, 각 장작의 ‘수정’으로 오타나 잘못 적은 내용을 고칩니다. 원문을 채운 입력창에서 ‘수정 저장’을 누르면 즉시 기록에 반영됩니다.
- 장작 수정은 원래 작성 날짜·순서·개수와 불 단계·진행도·냉각 기준 시각을 유지합니다. 보관한 불의 장작도 수정할 수 있으며 보관 상태와 이력은 그대로 남습니다. 수정한 원문은 다음 관계 분석에 사용합니다.
- 관심사와 기록은 현재 기기 또는 브라우저의 로컬 저장소에 보관됩니다.
- 저장 실패 시 입력창에 초안을 유지하며 다시 저장할 수 있습니다.
- 홈에서 아래로 스크롤하거나 위로 쓸어 올리면 별도의 ‘전체 분류’ 페이지가 열립니다. 하단 ‘전체 분류 보기’ 버튼으로도 이동할 수 있습니다.
- 전체 분류에는 기록이 없는 관심사도 표시하며, 각 불의 단계와 장작 수를 확인할 수 있습니다. 카드를 누르면 해당 불의 홈으로 돌아갑니다.
- 전체 분류의 위쪽 화살표로 이전 불에 돌아가거나, ‘새 불 피우기’ 카드에서 관심사를 추가할 수 있습니다.
- 전체 분류 맨 위에서 아래로 당기거나 위쪽으로 스크롤하면 이전 불의 홈으로 돌아갑니다. 목록 중간에서 시작한 드래그는 목록 스크롤로 처리합니다.
- 상단 + 왼쪽의 ‘관계’ 버튼에서 관심사 관계도를 엽니다.

## 불의 보관과 타임라인

‘꺼진 불도 과거에 실제로 타고 있었다’를 기준으로, 일반적으로 불을 내려놓을 때는 보관을 권합니다.

- 보관한 불은 홈의 활성 목록에서 빠지고, 전체 분류의 ‘보관한 불’ 탭에서 기록을 열 수 있습니다.
- 보관 이유는 선택 사항입니다. 관심 소멸·목표 달성·다른 관심사로의 전이·휴식·직접 입력을 구분하며, 전이 또는 직접 입력에서는 짧은 설명도 남길 수 있습니다.
- 장작의 내용과 날짜는 바꾸지 않습니다. 보관·재시작 시각과 이유를 이력으로 추가하며, 기록 화면의 타임라인에서 함께 봅니다. 반복해서 보관하거나 다시 시작해도 이전 이유를 덮어쓰지 않습니다.
- ‘다시 불붙이기’는 같은 관심사와 기록을 유지하면서 1단계 작은 불씨로 시작합니다. 보관 중에는 장작을 추가하지 않습니다.
- 보관된 불도 관계도에 남습니다. 회색 불과 ‘보관’ 표기로 구분하고, 기록 및 보관 이유를 확인할 수 있습니다. 전이 사유는 향후 AI 분석에 사용할 구조화된 값(`transitioned`)과 원문으로 보존합니다.
- 완전 삭제는 별도 확인에서 ‘관련 장작 기록과 AI 관계 분석도 함께 삭제됩니다.’를 알립니다. 확인하면 해당 관심사의 장작·보관 이력을 지우며, 그 불을 포함한 관계는 더 이상 생성하지 않습니다.
- 불이 자연적으로 0단계가 되는 것과 사용자가 보관하는 것은 별개의 상태입니다. 마지막 활성 불을 보관해도 과거 기록은 남고, 새 불을 만들 수 있습니다.

저장 형식 v3은 v1·v2의 기존 기록을 보존하며 전환합니다. 기존 기록은 활성 상태와 빈 이력으로 읽습니다. 저장에 실패하면 상태를 바꾸지 않고 재시도할 수 있습니다. 이전 앱이 보관 이력을 무시하고 덮어쓰지 않도록 v3을 구분하며, 이전 형식으로 되돌리는 파괴적 변환은 수행하지 않습니다.

## 관계도

어두운 자주색 배경에 불 모양의 노드를 배치합니다. 노드 크기는 현재 불의 단계이며, 연결선은 서버가 반환한 밀접도(`score`)가 높을수록 굵고 선명합니다. 중심 인력·노드 반발력·연결의 탄성으로 배치를 계산하며, 실제 관계도는 서버가 반환한 모든 연결을 표시하며, 예시 관계도만 한 불의 선을 최대 3개로 제한합니다.

- 불 선택: 해당 불과 직접 연결된 이웃을 강조합니다. 아래의 연결 이름으로도 설명을 열 수 있습니다.
- 선 선택: 연결 이유, 양쪽의 원본 기록과 날짜, 서버의 행동 제안(`suggestion`)을 하단 시트에서 확인합니다.
- 근거 기록의 ‘이 불로 가기’: 실제 관심사의 홈으로 이동합니다.
- 보관된 불의 ‘기록 보기’: 보관 이유와 과거 기록을 열고 필요하면 다시 불붙입니다.
- 노드 드래그, 배경 이동, 핀치 또는 +/−로 확대·축소, 전체 배치 복원을 지원합니다.
- 작은 빛과 위치 변화는 애니메이션 줄이기 설정에 따라 멈춥니다.

‘내 관심사’의 **관계 분석하기**를 누르면 실제 장작 원문을 백엔드에 전송합니다. ‘예시 관계도’는 가상의 관심사와 로컬 공통점 분석을 사용하는 별도 모드이며 서버를 호출하지 않습니다. 실패 시 로컬 분석이나 예시를 대신 표시하지 않습니다.

## AI 서버 연결

[백엔드 API 문서](https://github.com/rmdkarhdwn/jangjak_diary_backend)의 `POST /analyze-relations`를 사용합니다. `AI_BASE_URL`은 서버 주소만 담고, **LLM API 키는 백엔드 `.env`에만** 설정합니다. 앱의 기본 주소는 비어 있으므로 실행 시 명시해야 합니다.

```sh
# Mac과 휴대폰을 같은 Wi-Fi에 연결합니다.
# 휴대폰 브라우저에서 http://<Mac의 Wi-Fi IP>:3000/health 를 먼저 확인합니다.
flutter run --dart-define=AI_BASE_URL=http://<Mac의 Wi-Fi IP>:3000

# Mac 브라우저에서 실행할 때
flutter run -d chrome --web-port=8080 --dart-define=AI_BASE_URL=http://127.0.0.1:3000
```

실기기의 `localhost`는 휴대폰 자체입니다. `0.0.0.0`도 클라이언트 주소로 사용하지 않습니다. Mac의 Wi-Fi 주소는 `ipconfig getifaddr en0` 또는 시스템 설정에서 확인합니다. `/health`는 서버 생존만 확인하며 LLM 키의 유효성은 보장하지 않습니다.

- **요청**: 실제 관심사 ID, 제목, 관심사별 최근 30개의 비어 있지 않은 장작 `text` 원문을 `logs: string[]`으로 보냅니다. 공백만 있는 기록은 제외합니다. 기록이 없는 관심사는 `candidateInterests`에 ID·제목만 보내 직접 언급의 연결 대상으로 사용할 수 있게 합니다. 빈 로그나 가짜 기록은 추가하지 않습니다. 중복·빈 ID는 전송 전에 오류로 안내합니다. 원문 앞뒤 공백·줄바꿈은 보존하고, 2,000자를 넘는 기록은 임의로 자르지 않습니다.
- **제한**: 기록이 있는 관심사와 후보를 합쳐 최대 12개, 요청은 최대 128 KiB입니다. 초과하면 일부 관심사를 몰래 제외하지 않고 오류로 안내합니다. 모든 기록이 비어 있으면 요청하지 않습니다. 기록이 하나만 있어도 다른 관심사 후보가 있으면 분석하며, 실제 정상 빈 관계 응답은 그대로 사용합니다.
- **응답**: `source`/`target`을 실제 ID로 매핑하며 `score`(0~1)는 재계산·재가중·로컬 임계값 필터 없이 사용합니다. `topic`/`motivation`/`behavior`/`transition`을 구분하고 전이는 source → target 방향으로 표시합니다. `basis: shared_logs`는 양쪽 기록의 공통점, `basis: explicit_reference`는 source 기록이 target의 관심사를 직접 다룬 주제 관계입니다. basis가 없는 이전 응답은 shared_logs로 해석합니다. 설명은 `summary`, 행동 제안은 `suggestion`을 그대로 사용합니다. shared_logs의 근거는 양쪽 원문과 대조하고, explicit_reference의 근거 1개 이상은 source의 원문·날짜에만 연결합니다. 바텀시트에서 어느 관심사 기록에서 나온 연결인지 표시합니다.
- **실패 처리**: 정상 `relations: []`와 오류를 구분합니다. HTTP 오류의 `error.code/message`, 잘못된 JSON·ID·점수·근거, 연결 실패, 시간 초과를 안내하며 다시 시도할 수 있습니다. 중복 요청을 막고 55초 후 HTTP 요청을 취소합니다. 분석 결과는 영구 저장하지 않으므로 삭제된 관심사의 오래된 연결을 복원하지 않습니다.
- **시간·보관 정보**: 현재 계약대로 문자열 로그만 전송합니다. 보관 이유·이력은 로컬에 유지되며 아직 별도 필드로 전송하지 않습니다. 백엔드는 날짜가 없는 문자열 로그에서 시간 점수를 0으로 처리하므로, 실제 시간 기반 전이 분석에는 이후 날짜 포함 계약 연결이 필요합니다.
- **네트워크**: Android는 인터넷 권한을 추가하고, HTTP 허용 설정은 `src/debug/`에만 둡니다. iOS Debug만 `Runner/Info-Debug.plist`의 로컬 네트워크 설명과 HTTP 허용 설정을 사용하며 Release/Profile의 `Info.plist`에는 HTTP 예외를 추가하지 않습니다. 이는 [Flutter 개발 빌드 설정 안내](https://docs.flutter.dev/release/breaking-changes/network-policy-ios-android)를 따릅니다. 배포 서버에는 HTTPS를 사용하세요.
- **웹 CORS**: 백엔드 `CORS_ORIGINS`에 웹 앱의 정확한 출처를 넣습니다. 기본 8080 출처 외에 이 채팅 미리보기는 `http://127.0.0.1:55322`를 허용해야 합니다. HTTPS 웹 앱에서 HTTP 서버를 호출하면 브라우저가 차단할 수 있습니다.

### 로컬 HTTP 통합 검증

실제 Flutter HTTP 클라이언트 → 실제 Fastify → 실제 SDK → 백엔드 저장소의 기존 Postman 공급자 대역을 연결합니다. 실제 API 키나 `.env`를 읽지 않으며 클라우드에 업로드하지 않습니다. 백엔드 저장소가 앱의 형제 폴더에 있어야 합니다(`BACKEND_DIR`로 변경 가능).

```sh
# 터미널 1: 백엔드 폴더에서 기존 공급자 대역 시작
cd ../jangjak_diary_backend
postman simulation run postman/simulations/relations-local/relations-local.sim.yaml --port 4900 --output ndjson --no-history

# 터미널 2: 앱 폴더에서 실제 백엔드를 대역에 연결
../jangjak_diary_backend/node_modules/.bin/tsx tool/relation_simulation_server.mts

# 터미널 3: 앱 폴더에서 HTTP 왕복 검증
flutter test --no-pub test_integration/relation_api_http_test.dart
```

정상 score=0.66, 기록 없는 후보에 대한 직접 언급 score=0.95와 한쪽 근거, 정상 빈 배열, 공급자 오류, 잘못된 AI JSON의 전파를 검증합니다. 이 검증은 실제 Haiku의 사용 권한·응답 품질이나 휴대폰에서 Mac까지의 연결을 증명하지 않습니다. 자세한 실행 근거는 `tool/relation-simulation.context.md`에 남깁니다.

## 불의 단계

| 단계 | 이름 | 상태 | 누적 장작 기준 |
| --- | --- | --- | --- |
| 0 | 재 | 잠시 쉬어가는 중 | 0개 |
| 1 | 작은 불씨 | 거의 꺼진 상태 | 1개 |
| 2 | 살아난 불씨 | 관심이 다시 생김 | 3개 |
| 3 | 작은 불 | 꾸준히 생각나는 상태 | 5개 |
| 4 | 큰 불 | 현재 꽤 몰입 중 | 7개 |
| 5 | 활활 타는 불 | 최상위 관심 상태 | 9개 |

새 관심사는 0단계에서 시작하고, 식지 않고 계속 장작을 넣으면 누적 1·3·5·7·9번째 장작에서 단계가 올라갑니다. 즉 첫 단계에는 1개, 이후 단계마다 2개씩 추가로 필요합니다. 홈에는 다음 단계까지 필요한 장작 수를 표시합니다. 최고 단계에서 추가한 기록도 보존하며 마지막 장작 시각을 갱신합니다.

마지막 장작 이후 72시간마다 1단계씩 줄어 0단계에서 멈춥니다. 단계가 내려가면 진행 중이던 장작 수는 초기화하고 내려간 단계에서 다시 쌓습니다. 과거 기록 개수로 불을 자동 복구하지 않으며, 기록 원문과 날짜는 모두 남습니다. 보관한 불의 ‘다시 불붙이기’는 기존처럼 1단계에서 시작하되 다음 단계 진행도는 초기화합니다.

앱을 닫아 둔 시간도 반영하며, 앱을 다시 열거나 실행 중 1분마다 현재 상태를 갱신합니다. 저장 형식 v4는 다음 단계 진행도까지 보존합니다. v1~v3 기록은 기존 단계·냉각 기준 시각·내용·날짜·보관 이력을 유지하고 진행도 0으로 한 번만 전환합니다.

불의 크기·빛·불티가 단계에 따라 달라집니다. 현재 보이는 불만 계속 움직이며, 시스템의 애니메이션 줄이기 설정이 켜져 있으면 지속 움직임을 멈춥니다.

## 구성

- `lib/home/`: 홈, 캐러셀, 전체 분류 페이지, 입력 및 기록 시트
- `lib/relationships/`: 관계도, API 클라이언트, 힘 기반 배치, 예시 분석, 연결 설명 시트
- `lib/diary/diary_store.dart`: 기록 모델과 로컬 저장
- `lib/theme/diary_theme.dart`: Figma 색상과 글꼴
- `assets/figma/`: Figma 원본 SVG와 벽난로 렌더링 이미지
- `assets/fonts/`: Noto Sans KR, Noto Serif KR 및 OFL 라이선스
